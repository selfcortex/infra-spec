# ADR — архитектурные решения

> L2. Формат: контекст → решение → последствия. Нумерация устойчивая —
> решения не удаляются, только помечаются `superseded`.

---

## ADR-001: CPU-эмбеддер на том же pinned-образе llama.cpp
**Контекст**: GPU занята 27B-моделью полностью; нужен эмбеддер для RAG.
**Решение**: `bge-m3-q8_0.gguf` (1024-dim, matryoshka, кросс-лингва) на
`ghcr.io/ggml-org/llama.cpp@sha256:6da04cde…` с `-ngl 0`, `-c 8192 -b 2048 -ub 4048`.
**Последствия**: VRAM не трогаем; эмбеддинг чанка ~10–30 мс на 12 CPU;
`-b 2048` обязателен — в `--embeddings` режиме каждый инпут должен влезть в
один physical batch (баг №9). Запасной план (Qwen3-Embedding-0.6B) не
понадобился.

## ADR-002: MCP-first без LLM-прокси
**Контекст**: варианты — проксировать LLM с inject'ом поиска, виртуальная
модель `+rag`, или инструмент.
**Решение**: MCP-инструмент `search`, который агент (opencode) вызывает сам.
`rag-core` в MCP-пути не знает про LLM.
**Последствия**: из стека убраны прокси `/v1`, Chatbox-обёртки; Phase 2
(прокси + `+rag`) — отдельное решение, не блокирует Phase 1.

## ADR-003: Прикрепление к чужому стеку через внешнюю сеть `ai-net`
**Контекст**: RAG — отдельный репо; нужен доступ Prometheus → rag-core и
(Phase 2) rag-core → llama.
**Решение**: external bridge `ai-net` (создаётся `make init` в RAG; оба
compose-файла объявляют её `external: true`); участники: `rag-core`,
`llama-qwen27b` (алиас `llama`), `llama-prometheus`.
**Последствия**: минимальные правки ai-compose (2 сервиса + сеть); Docker DNS
даёт имена контейнеров без публикации портов; алиас `llama` активен
runtime-командой, compose-версия подхватится после следующего `up`.

## ADR-004: `rag-net` — internal bridge для ядра
**Контекст**: embedder и qdrant не должны быть досягаемы с хоста/интернета.
**Решение**: `rag-net: internal: true`; rag-core — на обеих сетях (мост).
**Последствия**: embedder без API-ключа (физически закрыт), qdrant ключён
даже внутри (глубина); наружу торчит только rag-core:8090 (127.0.0.1).

## ADR-005: mcp 2.3.0 (v2 API), не `mcp<2`
**Контекст**: пин «по свежести» попал в v2, где `FastMCP` удалён (баг №4).
**Решение**: принять v2: `MCPServer` из `mcp.server.mcpserver`; саб-апп
монтируется на `/` (дефолтный `streamable_http_path=/mcp`); lifespan **хостового**
приложения обязан войти в `async with mcp.session_manager.run()` (lifespan
смонтрованного саб-аппа не исполняется); auth-обёртка — только `path.startswith("/mcp")`.
**Последствия**: REST-роуты (`/search`, `/ingest`, `/metrics`) зарегистрированы
до mount'а и имеют приоритет; one-shot JSON-RPC в `/mcp` невозможен — нужен
handshake, отсюда REST-дубль `/search` для CLI.

## ADR-006: Point id = UUID(sha256(path+'\0'+body)[:16])
**Контекст**: qdrant принимает только UUID или uint64 (баг №11); нужен
детерминированный idempotent-инджест.
**Решение**: первые 128 бит sha256 от `path + '\0' + body`.
**Последствия**: повторный инджест того же чанка бьёт в ту же точку;
идентичные тела → один UUID → бесплатная дедупликация (159 чанков → 158 точек,
разгадано и верифицировано 158/158).

## ADR-007: `rel_path` с префиксом имени корня
**Контекст**: два корня корпуса (`ai-compose`, `rag`); «относительный путь»
дал коллиз `README.md` и молчаливое стирание чанков (баг №12 — худший).
**Решение**: `rel_path = <имя-корня>/<внутренний-путь>`:
`ai-compose/README.md` ≠ `rag/README.md`.
**Последствия**: `delete_by_path` и unique-key глобально уникальны;
`get_document` опознаёт префикс корня. Урок: unique key = путь, уникальный
**по всему корпусу**.

## ADR-008: In-memory очередь инджеста, state.json на диске
**Контекст**: корпус = десятки файлов, не тысячи.
**Решение**: очередь в словаре, один asyncio-worker; `state.json`
(path → mtime/hash) в volume; инкремент = delete_by_path + upsert;
полный рескан — `POST /ingest {}`.
**Последствия**: нет Redis; рестарт rag-core теряет queued-джобы (допустимо —
рескан идемпотентен); state с устаревшей схемой ключей безопасен
(монотонное расширение, баг №14).

## ADR-009: `/metrics` анонимный, Bearer — только на `/mcp*` (+`/search`, `/ingest`)
**Контекст**: Prometheus должен скрейпить rag-core без хранения ключа;
MCP-эндпоинт — с аутентификацией.
**Решение**: auth-обёртка пускает Bearer-проверку только на пути, начинающиеся
с `/mcp`; `/metrics` — открыт (данные: счётчики/латентности, не секреты).
**Последствия**: job `rag` в Prometheus без credentials_file; ротация MCP-ключа
не затрагивает мониторинг.

## ADR-010: Мониторинг — file_sd + дашборд-файл в чужом стеке
**Контекст**: нельзя поднимать второй Prometheus/Grafana.
**Решение**: prometheus прицеплен к ai-net; `job_name: rag` с
`file_sd targets/rag.yml` (`rag-core:8090`, без auth); дашборд
`grafana/dashboards/rag.json` (uid `rag`) — подхватывается file-provider'ом.
**Последствия**: в ai-compose 2 новых файла + 1 job + сеть; дашборд живёт без
рестарта Grafana; `refresh_interval: 30s` — таргет можно переключить одной
строкой (паттерн из job `llama`).

## ADR-011: bge-m3 как эмбеддер (кросс-лингва)
**Контекст**: корпус EN, запросы RU (и наоборот).
**Решение**: bge-m3 Q8_0: 1024-dim, multilingual, matryoshka.
**Последствия**: RU→EN поиск работает с первого раза (верифицировано);
запасной план Qwen3-Embedding-0.6B с instruction-префиксом — в резерве
(вернуться при деградации кросс-лингвы, см. `tasks.md`).

## ADR-012: websearch — обособленный стек
**Контекст**: SearXNG + Crawl4AI нужны агенту; к мониторингу LLM-стека
отношения не имеют.
**Решение**: свой compose (`search-net`), порты только 127.0.0.1
(`8081` SearXNG, `11235` Crawl4AI), агент ходит через shell/curl (MCP нет).
**Последствия**: ноль правок в других стеках; не мониторится (осознанно —
не LLM-нагрузка); типовой пайплайн: `/search` → URL → `/crawl` → markdown.

## ADR-013: Dify 1.20.0 — GUI-стек рядом с RAG (не замена)
**Контекст**: нужен GUI для индексации специк (в т.ч. PDF). RAGFlow (сценарий A —
замена RAG-стека) отклонён: ES+MySQL+MinIO+NATS+ClickHouse, ~8–12 GiB RAM,
ломает принцип «без дублей». Dify — легче (Postgres+Weaviate+Redis).
**Решение**: Dify 1.20.0 как **отдельный самодостаточный стек** `/mnt/GameLinux/dify`,
свой compose, свой вектор-стор (weaviate, дефолтный профиль).
Интеграция минимальная:
- эмбеддинги — внешний OpenAI-совместимый провайдер = наш `rag-embedder`
  (`docker network connect --alias embedder` в сеть Dify), bge-m3 1024-dim;
- LLM — `llama-qwen27b` через уже опубликованный LAN-порт `192.168.1.215:8080`;
- наружу: только GUI `127.0.0.1:8888` (nginx 80); 443 и plugin-debug 5003 не публикуются.
RAG-стек (qdrant + rag-core + MCP агента) **не трогается** — два контура:
агент → MCP → qdrant; человек → GUI Dify → weaviate.
**Последствия**: +16 контейнеров, ~4–6 GiB RAM; embedder получает второй
интерфейс (сеть Dify) — теоретически может выйти в интернет (llama.cpp сам
не делает исходящих запросов); два векторных хранилища осознанно (изолированы
по стекам, разные пользователи данных). RAGFlow-клон удалён, сценарий A отброшен.
