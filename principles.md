# Принципы и контроль качества

> L2. Что мы строго соблюдаем, зачем, и как проверяем. Формулировки — итог
> сборки RAG (см. `postmortem-rag-build.md`, раздел «Уроки»).

---

## 1. Архитектурные принципы

### 1.1 Отдельный репозиторий, прикреплённый стеком
Новый сервис = свой каталог/репо, **не** слит в чужой стек и **не** автономный
микро-стеk со своим мониторингом. Стык — одна внешняя docker-сеть (`ai-net`).
*Почему*: независимый lifecycle, минимальная поверхность правок в чужом репо.

### 1.2 Минимальные правки чужого стека
В ai-compose для подключения RAG изменено ровно: `docker-compose.yml`
(2 сервиса + внешняя сеть), `prometheus.yml` (1 job), 2 новых файла
(`targets/rag.yml`, `dashboards/rag.json`). Всё остальное — в RAG-репо.
*Контроль*: `git diff` на чужом репо должен читаться как чужеродный минимум.

### 1.3 MCP-first, агент решает сам
Поиск — инструмент, который **агент** вызывает сам. Нет LLM-прокси, виртуальных
моделей, Chatbox-обёрток в MCP-пути. `rag-core` в MCP-пути **никогда не звонит
в LLM** — только в эмбеддер. *Почему*: модель лучше знает, когда искать;
прокси добавляет латентность и точку отказа.

### 1.4 Мониторинг без дублей
Никакого нового Prometheus/Grafana. Метрики нового сервиса скрейпятся
существующим Prometheus: внешняя сеть + file_sd + дашборд в существующий
Grafana. *Почему*: два TSDB — два источника правды.

### 1.5 Пины = API-контракт
Образы — только по digest (`@sha256:`), pip — только по версиям.
**Пинить после** чтения migration guide, а не по свежести.
*Почему*: баг №4 — `mcp==2.3.0` «по свежести» = v2 с удалённым `FastMCP`.

### 1.6 Секреты вне git, ключ на каждом конце
`secrets/` + `.env` — gitignored во всех репо. Ключи генерируются `make init`.
Qdrant ключён **даже внутри** internal-сети. `/metrics` — намеренно анонимный
(Prometheus скрейпит без ключа); Bearer — только на `/mcp`, `/search`, `/ingest`.
*Почему*: анонимный /metrics — контракт мониторинга, а не дыра: endpoint без
данных-секретов на закрытой сети.

### 1.7 Сети по уровню доверия
- `internal: true` — для сервисов, которым не нужен наружный доступ
  (embedder, qdrant): физически недосягаемы с хоста/интернета.
- Внешняя bridge-сеть — единственное окно между стеками.
- Публикация портов: LAN-интерфейс для UI (Grafana), `127.0.0.1` — для всего
  остального. `0.0.0.0` — никогда.

### 1.8 Детерминированные идентификаторы
Point id = `UUID(sha256(path+'\0'+body)[:16])`: повторный инджест идемпотентен,
дедупликация одинаковых чанков — бесплатно. **Unique key = глобально
уникальный путь** (с префиксом корня), а не «относительный от чего-нибудь».
*Почему*: баг №12 — два `README.md` молчаливо стирали чужие чанки.

### 1.9 Healthcheck по содержимому образа
Не по привычке (`curl`), а по тому, что в образе на самом деле.
Qdrant: нет curl/wget, dash без `/dev/tcp` → спас `perl -MIO::Socket::INET`.
*Правило*: `docker run --rm --entrypoint sh <image> -c 'ls /bin'` до написания
healthcheck.

### 1.10 GPU — основной модели, CPU — всему остальному
27B-модель занимает VRAM полностью; эмбеддер bge-m3 (~605 MiB GGUF) — на CPU
(`-ngl 0`). 12 ядер эмбедят чанк за десятки мс — GPU для этого не нужна.

## 2. Контроль качества

### 2.1 Обязательные проверки

| Что | Команда/метод | Когда |
|---|---|---|
| Конфиг валиден | `docker compose config -q` | после любой правки compose |
| Стек здоров | `docker compose ps` — все `(healthy)` | после `up` |
| Скачанный файл цел | размер + `sha256sum`, сверка с LFS `oid` через HF API | после любого скача (aria2 resume ненадёжен) |
| Индекс согласован | count точек = count чанков − дедупы; набор путей полный | после любого инджеста |
| ID точек верны | пересчёт `UUID(sha256(path+'\0'+body))` из сохранённого текста, сверка 100% | после миграции схемы |
| Поиск отвечает | 3+ живых запроса (EN, RU, смешанный), топ-хиты осмысленны | после инджеста/фиксов |
| MCP-эндпоинт валиден | полный handshake: initialize → session id → initialized → tools/list → tools/call | после правок main.py |
| Мониторинг жив | `up{job="rag"}=1` в Prometheus; счётчики растут после живого поиска | после интеграции |
| Git чистый | `git status`: секреты/.env/личные файлы не в индексе | перед каждым push |

### 2.2 Правила верификации (анти-«тихий баг»)

1. **Сверять count + набор путей**, а не только «ошибок нет». Баг №12 не дал ни
   одной ошибки — только странный топ-1.
2. **Сверять идентификаторы против сохранённого состояния**: пересчитать ID из
   сохранённого текста и сравнить со всеми точками (158/158 = доверие).
3. **Тихие баги опаснее громких**: после любой миграции ключей/путей — полный
   пересчёт, а не «посмотрим в логах».
4. **Состояние с устаревшей схемой — не катастрофа**, если схема ключей
   расширяется монотонно: старые ключи просто никогда не совпадут (баг №14).
5. **Один edit = один ход + верифификация** (лимит сессии ~20k токенов):
   перечитывать полуприписанный файл дороже, чем дробить.

### 2.3 Инструментальные правила

| Правило | Почему |
|---|---|
| Не `pkill` по паттерну, вхождением в который является сама команда | убивает собственную оболочку (SIGTERM, exit 143) |
| `$` в compose-строках — валюта интерполяции: healthcheck'и писать без `$` | `my $s = …` → пустая строка + warning |
| `docker run --entrypoint grep -c …` — `-c` парсится как cpu-shares | через `sh -c 'grep -c …'` |
| MCP one-shot не существует: streamable-HTTP требует handshake | для CLI — отдельный REST `/search` |
| Пины проверять живьём: `python3 -c "import …; print(api)"` в целевом образе | документация отстаёт от версий (qdrant-client 1.20) |
| `docker run --rm --entrypoint python3 img -c "import main"` — ловить ImportError до `up` | экономит циклы build→up→logs |

## 3. Цели (что «хорошо» для этого хоста)

1. **LLM — на GPU, всегда доступна**: Chatbox/LAN-клиенты; 27B не сбивается
   другими сервисами.
2. **Агент сам знает, где искать**: доки — через RAG (MCP), интернет — через
   websearch (curl). Никакого ручного «посмотри в README».
3. **Один TSDB, один Grafana**: вся наблюдаемость стека в одном месте;
   дашборд нового сервиса провиженится файлом, без кликов в UI.
4. **Наружу торчат только намеренные окна**: `8080` (llama), `3000` (Grafana),
   три localhost-порта. Всё остальное — в закрытых сетях.
5. **Любой сервис воспроизводим**: pinned digest'и, секреты генерируются
   скриптом, запуск — одна команда.
6. **Документация живёт с кодом**: изменение compose без правки `infra-docs`
   = незакрытая задача (см. `tasks.md`).
