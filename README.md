# infra-docs — документация инфраструктуры хоста

Личный репозиторий: описание трёх стеков (`ai-compose`, `RAG`, `websearch`),
принципов, решений и задач. Для пользователя и для анализа Claude'ом.

Хост: CachyOS, 12c/31G, RX 6800 XT (ROCm), LAN `192.168.1.215`.

## Что где лежит

| Файл | Слоё | Что внутри |
|---|---|---|
| `map.md` | L1 | Карта: сети, порты, контейнеры, потоки данных (A–D), секреты, порядок запуска |
| `principles.md` | L2 | Принципы, цели, контроль качества (правила верификации) |
| `decisions.md` | L2 | ADR: архитектурные решения — контекст → решение → последствия |
| `tasks.md` | L3 | Задачи: done / open / deferred / dropped, с датами и коммитами |
| `runbook.md` | L3 | Эксплуатация: запуск, ротация ключей, реинджест, «что делать если X» |
| `postmortem-rag-build.md` | архив | Полный разбор сборки RAG: 14 багов с дословными ошибками, уроки |
| `archive/` | архив | Черновики и устаревшие заметки |

## Слои

- **L0** — этот README: один экран, где что лежит.
- **L1** — `map.md`: *что есть* (факты: сети, порты, потоки).
- **L2** — `principles.md` + `decisions.md`: *почему так* (принципы и решения).
- **L3** — `tasks.md` + `runbook.md`: *что делать* (состояние и операции).

## Правила ведения

1. **Один источник правды**: compose-файлы описывают *что*, эти файлы — *почему*.
   Любое изменение инфраструктуры в compose = правка документации **в тот же коммит**.
2. **Факты проверяются, а не перепечатываются**: порты/сети/образы — только из
   живых compose-файлов и `docker network inspect`, не по памяти.
3. **Статусы задач** — ровно четыре: `done` / `open` / `deferred` / `dropped`,
   каждый с датой и ссылкой (коммит, файл, issue).
4. **Count check**: после любого инджеста/миграции сверять счётчики
   (чанки ↔ точки ↔ пути) и набор путей.
5. **Язык**: русский (для человека и Claude), имена файлов — английские.
6. Документ, не привязанный ни к одному коммиту, считается устаревшим.
